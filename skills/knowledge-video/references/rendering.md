# 完整渲染（Claude Code 本地）

只有在用户本机跑 Claude Code、并且要真实成片时才用这一节。网页版只做剧本包，最多加一个单文件 HTML 的开场动画预览，标明「预览，不是成片」。

## 上游流水线

成片流水线来自 [andyhuo520/vibe-knowledge](https://github.com/andyhuo520/vibe-knowledge)（MIT）：旁白驱动的代码渲染引擎（逐帧录制 1080p60）、配音、混音、OCR 回读质检。本仓库不随带引擎、字体、默认配乐和默认音色，用户需按上游 README 自己安装：

- 上游的 `vibe-knowledge` 和 `ai-teardown` 两个 skill 都要装；
- Python（numpy、scipy、pillow、playwright + Chromium headless shell）、ffmpeg；
- 配音服务的密钥放环境变量或用户目录下的配置文件，不写进项目文件；
- 可选的生成平台（配图、动态镜头、音效）按上游说明接入。

装好后按上游 SKILL.md 的命令走；本 Skill 的剧本包（事实清单、分镜旁白、风格卡）就是它的输入。

## 成片阶段的规矩

1. **先做 15–20 秒样片**：开场画面加配音试听，用户定了音色、语速和字号再铺开整期。
2. **花钱的生成先报价**：列出每个镜头的模型、提示词、数量和预估花费，等用户在对话里明确同意再提交。改了提示词、模型或数量就重新报价。只重做不满意的单张，不整批重来。
3. **只把代码画不好的镜头交给生成**：写实历史场景、自然现象、真实材质，以及全片最需要被记住的 1–3 个时刻。数据、地图、文字、图表、示意动画仍用代码画。
4. **结构即知识点的东西不用 AI 图**：文物、仪器、机械结构容易画错，改用代码线稿剖面，标「代码示意」。
5. **配音**：克隆音色只用用户本人或已获授权的声音；回读准确率低于 95% 的拍单独重配；同一拍里重复的词容易让逐字对齐失败，改写成不重复的说法。
6. **质检**：抽帧接触表逐张看；OCR 回读屏幕文字，与事实清单逐条对照；响度约 −14.5 LUFS、真峰值 ≤ −1 dBTP；超过 3 秒的静止画面要处理，超过 10 秒的冻结基本是录制出错，要重录。
7. **渲染队列**：多个会话共用一个渲染队列时只追加不覆盖，已有队列在跑就交给它，不要并行起第二个。
