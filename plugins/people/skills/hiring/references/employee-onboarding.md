# Employee Onboarding

Rules for a new hire's first 90 days, adapted and rewritten from `anthropics/knowledge-work-plugins` human-resources onboarding (Apache-2.0).

`people/hiring` runs the process up to the offer; this file starts when the offer is accepted. Product-user onboarding belongs to `product/onboarding-and-retention`, not here.

## What is needed

New hire name, role, team, start date and manager. Customise for the role: an engineer's onboarding looks different from a designer's.

## Pre-start (before Day 1)

- Send the welcome email with start date, time and logistics.
- Set up accounts: email, chat, and the tools for the role.
- Order equipment (laptop, monitor, peripherals).
- Add the hire to the team calendar and recurring meetings.
- Assign an onboarding buddy: a go-to person who is not the manager.
- Prepare desk or remote setup instructions.
- Confirm accounts and equipment are working the day before, not on the morning of Day 1.

## Day 1

A first day is about setup and people, not deep work. Do not overload it.

| Time | Activity | With |
| --- | --- | --- |
| Morning | Welcome and orientation | Manager |
| Morning | IT setup and tool walkthrough | IT / buddy |
| Midday | Team introductions | Team |
| Midday | Welcome lunch | Manager and team |
| Afternoon | Company overview and values | Manager |
| Afternoon | Role expectations and the 30/60/90 plan | Manager |
| Late | Free time to explore tools and docs | Self |

## Week 1

- Complete required compliance training.
- Read the key documentation for the role.
- One-to-one with each team member.
- Shadow key meetings.
- First small task or project assigned.
- End-of-week check-in with the manager.

## 30/60/90-day goals

Set three goals per horizon, each aligned to the role and measurable enough that the check-in can say whether it was met.

- **30 days.** Learn the systems, the people and the ways of working. Example: complete the tool and compliance setup, meet every teammate, ship the first small task.
- **60 days.** Contribute independently. Example: own a defined piece of work end to end, run a meeting or review without the manager present.
- **90 days.** Operate at the level the role was hired for. Example: deliver a scoped project, propose one improvement to the team's process, and agree the next quarter's goals with the manager.

Check-ins run at one week, two weeks and one month, then at each horizon, against the rubric used to hire.

## Key contacts and tools

| Person | Role | For what |
| --- | --- | --- |
| Manager | Manager | Day-to-day guidance |
| Buddy | Onboarding buddy | Questions, culture, navigation |
| IT contact | IT | Tool access, equipment |
| HR contact | HR | Benefits, policies |

List the tools access needed per tool, with the access level and whether it has been requested. Access that is still pending at Day 1 is a blocker, and the plan says so.

## Constraints

- Do not schedule deep work in the first week; the first week builds context and relationships.
- Do not leave the hire without a buddy or without a named contact for each kind of question.
- Do not invent start dates, equipment or access that has not been confirmed.
