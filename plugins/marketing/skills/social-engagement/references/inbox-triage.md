# Inbox Triage

After reading comments or DMs, triage before handling. Each item goes into exactly one bucket, judged in this order: spam → complaint → commercial → recruitment → fan question → other.

## 1. Spam / advertising (filter first, never reply)

Signs: mass-sent scripts, follow-for-follow or growth-service pitches, coin / investment / gambling, the same message pasted repeatedly, obvious bot wording.

Handling: do not reply, do not open links. Hide the comment or reply where the platform allows it; decline or delete the DM request. In the daily summary report only the count, not the content.

## 2. Complaint / dissatisfaction (show the user first, never reply directly)

Signs: unhappy with content, a product or a service; asks for a refund, a correction or an apology; heated tone.

Handling: do not argue, apologise or promise compensation. Collect the original text and link for the user and wait for the user to set the response line before drafting. Anything about refunds, compensation or legal issues always goes to the user; never state a position on it.

## 3. Commercial / partnership (summarise for the user, never negotiate)

Signs: brand collaboration, paid promotion, repost permission, media interview, event invitation, product exchange.

Handling: extract who they are, what kind of deal, budget or rate (write "not stated" when absent), timing, and contact details, and list them for the user. Do not discuss price, accept work or give a schedule; wait for the user's decision.

## 4. Recruitment / work opportunity (summarise for the user)

Signs: hiring, referral, headhunter, part-time or freelance offer, asking whether the user is looking for work.

Handling: extract company, role, location (and whether remote), salary range when given, and contact details, and list them for the user. Flag location constraints the user has stated (for example, remote only). Never agree to an interview or send an application.

## 5. Fan question (draft a reply, wait for confirmation)

Signs: asks about the content, wants a tutorial, a link or a recommendation, praises the content, shares their own experience, wants to know the user.

Handling: draft a reply by [reply-policy.md](reply-policy.md), in the other party's language. When the question can be answered, draft directly; when it needs the user's own information or an unknown fact, mark it "needs you to confirm" and hand it to the user with the draft.

## 6. Other

Small talk, greetings, emoji, @ mentions, messages with no substance: one line in the summary, no draft unless the user asks to reply.

## Triage record

One line per batch: date, platform, bucket, count, count needing the user. Do not copy full DM text into the record; summaries only.
